## 🎯 개요

Speckit의 `/speckit.specify` 명령을 사용하여 Figma 디자인 화면을 기반으로 정확한 기능 명세를 작성하는 방법을 안내합니다.

이 가이드는 **일기쓰기_최초** 화면을 실제 예시로 활용하여 실무에서 바로 적용 가능한 구조를 제시합니다.

---

## 📋 1. AI에게 제공해야 할 핵심 요소

### ✅ 필수 제공 항목 4가지

### 1️⃣ **Figma 디자인 자료**

- 전체 UI 스크린샷 또는 Figma 공유 링크
- 상태별 UI (기본/에러/확장/모달 열림 등)가 있으면 더욱 좋음
- 명확한 컴포넌트 네이밍과 레이어 구조

### 2️⃣ **화면 메타데이터 (Screen Context Info)**

- **화면 이름** (Screen Name)
- **화면 목적** (Screen Purpose)
- **대상 사용자** (User Type)
- **화면 진입 경로** (Navigation Path)

### 3️⃣ **기능적 제약 & 비즈니스 규칙**

- 필수 입력값
- 버튼 Enable/Disable 조건
- API 연동 여부
- 데이터 저장 구조
- 특정 조직/서비스 규칙

### 4️⃣ **명세 생성 규칙**

- AI가 생성해야 할 문서 형식 템플릿
- 포함되어야 할 섹션 구조

## 💡 3. 실전 예시: "일기쓰기_최초" 화면

### 제공된 화면 정보

**Screen Context:**

- **Screen Name**: 일기쓰기_최초
- **Purpose**: 사용자가 오늘의 기분을 선택하고 일기를 작성하는 모달
- **User Types**: 로그인한 일반 사용자
- **Navigation Path**: 일기보관함 → [+ 일기쓰기] 버튼 클릭

### AI에게 제공하는 완성형 프롬프트

```markdown
[Screen Context]
- Screen Name: 일기쓰기_최초
- Purpose: 사용자가 감정을 선택하고 제목과 내용을 입력하여 일기를 생성하는 화면
- User Types: 로그인한 일반 사용자
- Navigation Path: 일기보관함 → [+ 일기쓰기] 버튼 클릭 시 표시되는 모달 화면

[Functional Notes]
- 기분(mood) 선택 필수
- 제목(title)과 내용(content)은 선택 입력
- 기분 선택 완료 시 "등록하기" 버튼 활성화
- 저장 요청: POST /api/diary
- 저장 성공 시 모달 닫기 및 일기 목록 갱신
- 저장 실패 시 에러 메시지 표시

[Attached Figma Screen]
<이미지 첨부>

위 정보를 기반으로 Speckit /speckit.specify 포맷에 맞는
기능 명세서를 생성해줘.

명세는 아래 8개 항목을 반드시 포함해야 해:

1. Screen Info
2. Component Breakdown
3. User Interactions
4. Validation Rules
5. Business Logic
6. Data Requirements
7. UI Flow Description
8. Error & Edge Cases
```

### 생성되는 명세서 구조

### 1. **Screen Info**

- Name: 일기쓰기_최초
- Purpose: 일기 생성 모달
- User Types: 로그인 사용자
- Navigation Path: 일기보관함 → [+ 일기쓰기]

### 2. **Component Breakdown**

- **Modal Container**: 중앙 정렬, 반투명 배경
- **Modal Header**: "일기 쓰기" 제목
- **Close Button (X)**: 우상단, 모달 닫기
- **Question Text**: "오늘 기분은 어떠니요?"
- **Mood Radio Group**:
    - 평온하다
    - 설레요
    - 불안해요
    - 외나요 (외로워요 확인 필요)
    - 기타
- **Title Input**: 제목 입력 필드 (선택)
- **Content Textarea**: 내용 입력 영역 (선택)
- **Close Button**: "닫기" - 취소 액션
- **Submit Button**: "등록하기" - 저장 액션

### 3. **User Interactions**

**기분 선택:**

- 라디오 버튼 클릭 → 선택 상태로 변경 (⦿)
- 단일 선택만 가능
- 선택 시 "등록하기" 버튼 활성화

**텍스트 입력:**

- 제목 필드: 짧은 텍스트 입력
- 내용 필드: 멀티라인 텍스트 입력
- 모두 선택 사항

**버튼 액션:**

- 닫기/X 버튼: 모달 닫기 (입력 내용 확인 다이얼로그)
- 등록하기: 데이터 저장 및 모달 닫기

### 4. **Validation Rules**

```tsx
{
  mood: required,        // 필수
  title: optional,       // 1-100자
  content: optional      // 1-5000자
}
```

### 5. **Business Logic**

**등록 플로우:**

```
1. 기분 선택 확인
2. API 호출: POST /api/diary
3. 성공: 
   - 모달 닫기
   - 일기 목록 갱신
   - 토스트: "일기가 저장되었습니다."
4. 실패:
   - 에러 메시지 표시
   - 모달 유지
```

**버튼 활성화 조건:**

- 기분이 선택되면: 등록하기 버튼 활성화
- 기분 미선택: 등록하기 버튼 비활성화

### 6. **Data Requirements**

```tsx
interface DiaryEntry {
  mood: 'peaceful' | 'excited' | 'anxious' | 'lonely' | 'other';
  title?: string;
  content?: string;
  createdAt: Date;
  userId: string;
}
```

### 7. **UI Flow Description**

**초기 진입:**

```
일기쓰기 클릭
  ↓
배경 딤 처리
  ↓
모달 표시 (fade-in + scale-up, 300ms)
  ↓
기분 선택 대기
```

**정상 플로우:**

```
기분 선택
  ↓
(선택) 제목/내용 입력
  ↓
등록하기 클릭
  ↓
저장 처리
  ↓
모달 닫기
```

### 8. **Error & Edge Cases**

**네트워크 오류:**

- 에러 메시지: "네트워크 오류가 발생했습니다. 다시 시도해주세요."
- [재시도] 버튼 제공

**중복 작성 (하루 1회 제한 시):**

- "오늘 일기를 이미 작성하셨습니다."
- 모달 진입 차단

**세션 만료:**

- 로그인 페이지 리다이렉트
- 작성 중인 내용 localStorage 임시 저장

**입력 내용 있을 때 닫기:**

- 확인 다이얼로그: "작성 중인 내용이 사라집니다. 닫으시겠습니까?"
- [계속 작성] [닫기]

## 🚀 5. 실무 활용 팁

### ✅ DO (권장사항)

**1. What과 Why에 집중**

- "무엇을" 만들고 "왜" 필요한지 명확히 설명
- How(구현 방법)는 `/speckit.plan` 단계에서

**2. 구체적인 시나리오 제공**

- 추상적인 설명보다 실제 사용 상황 묘사
- "사용자가 일기를 작성하려고 할 때..."

**3. UI 스크린샷 필수 첨부**

- 전체 화면 + 상태별 변형
- 명확한 컴포넌트 레이블링

**4. 비즈니스 요구사항 우선**

- 기술 스택보다 비즈니스 규칙을 먼저
- API 스펙은 간략하게, 상세는 별도 문서로

### ❌ DON'T (피해야 할 것)

**1. 기술 구현에 집중하지 마세요**

- "React로 구현" → `/speckit.specify`에서는 불필요
- "REST API 사용" → 데이터 흐름만 명시

**2. 모호한 표현 피하기**

- "적절히 처리" → 구체적인 동작 명시
- "예쁘게 디자인" → 디자인 토큰으로 정의

**3. 가정하지 말기**

- "당연히 알 것" → 명시적으로 작성
- "보통 이렇게" → 프로젝트 컨텍스트 제공
