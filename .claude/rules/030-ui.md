## 1. Figma 디자인 구현 원칙

### 1.1 디자인 충실도

- Figma 링크가 제공되면, **제공된 디자인 그대로 구현**할 것
- 명시되지 않은 기능이나 스타일을 추가하지 말 것
- 디자이너의 의도를 존중하고 정확히 반영할 것

### 1.2 사이즈 정확성

- 모든 사이즈는 **Figma 수치와 동일하게** 처리할 것
- width, height, padding, margin 등 모든 spacing 값 준수
- 임의로 수치를 변경하지 말 것

### 1.3 구조 유연성

- Figma 구조가 잘못되었을 수 있음을 이해할 것
- Figma 구조를 맹목적으로 따르지 말 것
- **이미 만들어진 HTML/CSS 구조 안에서** 내부만 채우는 방식으로 작업할 것
- 기존 컴포넌트 아키텍처와 조화를 이루도록 구현할 것

### 1.4 히든 요소 처리 (필수)

- **Figma 노드 분석 시 `visible` 속성 반드시 확인**
  - `fills` 배열의 `"visible": false` 속성 확인
  - 노드 구조에서 해당 노드가 없는 경우도 확인
- **히든 요소는 CSS로 숨김 처리**
  - `display: none` 클래스 추가 (예: `.elementHidden`)
  - 조건부 렌더링보다 CSS 클래스 사용 권장 (구조 유지)
- **노드가 없는 경우 렌더링하지 않음**
  - Figma 구조에 없는 요소는 코드에서도 제외

## 2. 에셋(Icons/Images) 관리

### 2.1 경로 규칙 - 컴포넌트 기반 조직화

```text
public/
├── icons/
│   ├── layout/          # Layout 컴포넌트 전용 아이콘
│   ├── button/          # Button 컴포넌트 전용 아이콘
│   └── [component-name]/ # 각 컴포넌트별 폴더 분리
└── images/
    └── [component-name]/ # 각 컴포넌트별 이미지 폴더
```

**중요:** 중복 파일명 방지를 위해 반드시 컴포넌트별 폴더로 분리할 것

### 2.2 사용 방법

```tsx
/* ✅ 올바른 예 - Next.js Image 컴포넌트 (컴포넌트별 경로) */
import Image from 'next/image';

<Image
  src="/icons/layout/hamburger_close.svg"
  alt="Menu"
  width={20}
  height={20}
/>

/* ❌ 잘못된 예 - 컴포넌트 폴더 없이 직접 배치 */
<Image src="/icons/search.svg" alt="Search" width={20} height={20} />
```

### 2.3 아이콘 우선순위

**컴포넌트별 폴더에 아이콘이 없는 경우**:

1. Untitled UI에서 동일 아이콘 찾기 (`@untitledui/icons`)
2. React 컴포넌트로 교체
3. 불필요한 SVG 파일 삭제

```tsx
/* ✅ Untitled UI 아이콘 사용 (권장) */
import { SearchLg } from '@untitledui/icons';
<SearchLg size={20} />

/* ⚠️ SVG 파일은 Untitled UI에 없는 경우만 사용 */
import Image from 'next/image';
<Image src="/icons/component/custom-icon.svg" width={20} height={20} />
```

### 2.4 최적화 가이드

- Next.js Image 컴포넌트 사용 (자동 최적화)
- width/height 명시 필수 (Layout Shift 방지)
- alt 텍스트 필수 작성 (접근성)

### 2.5 Figma 노드 분석 체크리스트

Figma MCP로 노드 정보 추출 시:

1. **노드 구조 확인**
   - 각 자식 노드의 존재 여부 확인
   - 노드가 없으면 렌더링하지 않음

2. **Visible 속성 확인**
   - `fills` 배열의 `"visible": false` 확인
   - 히든 요소는 CSS 클래스로 숨김 처리

3. **수치값 정확성**
   - `absoluteBoundingBox`의 width, height 확인
   - 모든 spacing, sizing 값 정확히 반영

### 2.6 디자인 토큰 사용 원칙

**기본 원칙: 디자인 토큰 우선 사용**

- **Spacing**: `var(--spacing-*)` 토큰 사용
  - `--spacing-none`, `--spacing-xxs`, `--spacing-xs`, `--spacing-sm`, `--spacing-md`, `--spacing-lg`, `--spacing-xl` 등

- **Border Radius**: `var(--radius-*)` 토큰 사용
  - `--radius-none`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl`, `--radius-full`

- **Typography**: `var(--text-*)`, `var(--font-*)` 토큰 사용
  - Font Family: `var(--font-display)`, `var(--font-body)`
  - Font Size: `var(--text-xs)`, `var(--text-sm)`, `var(--text-md)` 등
  - Line Height: `var(--text-*--line-height)`

- **Colors**: `var(--color-*)` 토큰 사용 권장
  - `--color-white`, `--color-brand-600` 등

**예외 케이스: Figma 디자인 정확도 우선**

다음 경우에만 하드코딩 허용:

1. **Figma 디자인과 정확히 일치**시켜야 하는 경우
   - Figma에서 추출한 정확한 색상값 (`rgb()` 형식)
   - 디자인 토큰에 없는 특수한 수치

2. **승인 받은 경우**
   - 프로젝트 리드 또는 디자이너의 명시적 승인

```css
/* ✅ 올바른 예 - 디자인 토큰 사용 */
.button {
  padding: var(--spacing-lg);
  border-radius: var(--radius-md);
  font-family: var(--font-body);
  font-size: var(--text-sm);
}

/* ⚠️ 예외 케이스 - Figma 정확도 우선 (승인 필요) */
.specificColor {
  color: rgb(24 29 39); /* Figma Main Text 색상 */
  background-color: rgb(206 239 241); /* Figma Badge 배경색 */
}
```

**디자인 토큰 위치:**
- 정의: `frontend/src/styles/theme.css`
- 소스: `frontend/src/commons/constants/*.ts`
- 생성: `npm run generate:tokens`
